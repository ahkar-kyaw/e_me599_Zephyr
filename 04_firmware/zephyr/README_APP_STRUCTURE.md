# Project Structure Notes

This project was generated by STM32CubeMX, then reorganized so user-owned code is kept outside CubeMX-generated folders.

## CubeMX-owned areas

Treat these folders and files as generated or vendor-owned where possible:

- `Core/`
- `Drivers/`
- `Middlewares/`
- `STM32H723XG_FLASH.ld`
- `cmake/stm32cubemx/`

Use CubeMX USER CODE blocks for small startup hooks only.

## User-owned areas

Use these folders for project code:

- `app/platform/` for STM32H7 platform helpers such as DMA buffer placement
- `app/proto/` for protocol parsing with no HAL dependency
- `app/drivers/` for hardware-facing drivers
- `app/tests/` for temporary bring-up and debug code
- `linker/` for protected project-specific linker scripts

## Linker script

The actual CMake build uses:

```text
linker/STM32H723XG_FLASH_app.ld
```

The CubeMX-generated linker script remains at:

```text
STM32H723XG_FLASH.ld
```

The protected linker script contains the `.dma_buffer` section mapped to `RAM_D2`. This prevents ADC and USART DMA buffers from being placed in DTCMRAM.

## DMA buffers

DMA buffers are declared in:

```text
app/platform/dma_buffers.c
```

and exposed through:

```text
app/platform/dma_buffers.h
```

Current buffers:

- `adc1_raw[2]`
- `crsf_rx_dma_buf[512]`

After building, check the map file and verify these symbols are near address `0x30000000`.

## CRSF test

Temporary CRSF bring-up code lives under `app/tests/`.

`test_crsf.c` starts the CRSF driver, reads USART2 RX circular DMA data, and prints status over USART3.

This test module is intentionally separated from production robot logic. Later, production code should use `drv_crsf` and `proto_crsf` directly from a real task such as `task_crsf.c`.
